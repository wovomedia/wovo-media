# WOVO TikTok Content Posting setup

This guide corresponds to WOVO's implementation in:

- `app/api/integrations/tiktok/connect/route.ts`
- `app/api/integrations/tiktok/callback/route.ts`
- `lib/publishing/providers/tiktok.ts`

WOVO uses TikTok's official Login Kit and Content Posting API. It never asks for a TikTok password. Direct Post is feature-gated until TikTok completes its production audit.

## Step 1 — Open TikTok for Developers

Open [TikTok for Developers](https://developers.tiktok.com/) and sign in with the business-owned developer account that will control WOVO's application.

## Step 2 — Create or select WOVO's developer application

Open **Manage apps** and create or select the WOVO Media web application. Keep ownership with the company, not a contractor's personal account.

## Step 3 — Configure the WOVO application

Use the WOVO Media name, logo, support contact, privacy policy, terms, and data-deletion URLs from `https://wovomedia.com`. The application description must accurately say that customers generate or upload content in WOVO, review it, choose a connected destination, and explicitly approve a post or schedule before WOVO sends it.

## Step 4 — Configure website and domain information

Add `https://wovomedia.com` as the official website. Complete any website ownership verification shown by TikTok. Do not enter a temporary Vercel deployment domain as the production website.

## Step 5 — Register the exact callback URL

Add Login Kit for Web and register this exact static HTTPS redirect URI:

```text
https://wovomedia.com/api/integrations/tiktok/callback
```

It is generated by `socialRedirectUrl()` and used for both authorization and the server-side code exchange. Do not add query parameters or a trailing slash.

## Step 6 — Add Content Posting API

In the app's Products section, add **Content Posting API**.

## Step 7 — Configure Direct Post

Enable **Direct Post** for the Content Posting API. WOVO does not use browser automation or collect TikTok passwords.

## Step 8 — Request the required scopes

Request and obtain approval for:

```text
user.info.basic
video.publish
```

WOVO currently implements Direct Post. It does not request `video.upload`, because it does not send a draft to TikTok's inbox for the creator to finish manually.

## Step 9 — Complete TikTok review/audit

TikTok restricts posts from unaudited Direct Post clients to private visibility. Submit a production audit showing:

- WOVO's Connections screen and TikTok consent flow
- the current creator information being queried before every export
- privacy options populated only from TikTok's response
- comment, Duet, and Stitch controls respecting the creator's returned capabilities
- a final review/consent action before upload
- an in-progress state while TikTok processes the post
- success and failure states based on TikTok's status API
- disconnect/reconnect and token-expiry behavior
- WOVO's terms, privacy, and data-deletion pages

Do not set `WOVO_TIKTOK_DIRECT_POST_AUDITED=true` until TikTok confirms the audit.

## Step 10 — Verify the media URL property

WOVO uses `PULL_FROM_URL` because generated videos are stored by WOVO before publishing. In TikTok's URL properties widget, verify the exact host used by WOVO media. The default production setting is:

```text
wovomedia.com
```

If production media is served from a dedicated host, set that exact host in `WOVO_SOCIAL_MEDIA_HOST` and verify the same domain or URL prefix in TikTok. WOVO rejects temporary fal/provider URLs and any non-HTTPS, non-WOVO-controlled URL.

## Step 11 — Run the controlled test procedure

1. Add the test TikTok account to the app's allowed testers.
2. Add the production callback above.
3. Configure the environment variables below.
4. Set `WOVO_TIKTOK_TEST_POSTING_ENABLED=true` only in a controlled test deployment.
5. Leave `WOVO_TIKTOK_DIRECT_POST_AUDITED=false`.
6. Connect the test account from WOVO.
7. Run **Check publishing** and confirm creator information is returned.
8. Publish one rights-confirmed WOVO-owned test MP4 with privacy `SELF_ONLY`.
9. Confirm WOVO saves `publish_id`, shows **Publishing**, polls status, and saves provider proof only after `PUBLISH_COMPLETE`.
10. Turn the test flag off after the canary.

## Step 12 — Submit production access

After the controlled test passes, submit the Direct Post audit in TikTok for Developers. Provide the screen recording and policy URLs above. Wait for approval before showing customer-facing TikTok connection controls broadly.

## Production environment variables

Add these as server-only Vercel variables for Production (and Preview only when a controlled preview callback is separately registered):

```text
TIKTOK_CLIENT_KEY
TIKTOK_CLIENT_SECRET
WOVO_SOCIAL_TOKEN_ENCRYPTION_KEY
WOVO_SOCIAL_MEDIA_HOST=wovomedia.com
WOVO_TIKTOK_DIRECT_POST_ENABLED=false
WOVO_TIKTOK_DIRECT_POST_AUDITED=false
WOVO_TIKTOK_TEST_POSTING_ENABLED=false
```

`WOVO_SOCIAL_TOKEN_ENCRYPTION_KEY` must be 64 hexadecimal characters (32 random bytes). Never expose it as `NEXT_PUBLIC_*`.

After audit approval and a private/public canary, set `WOVO_TIKTOK_DIRECT_POST_AUDITED=true` and `WOVO_TIKTOK_DIRECT_POST_ENABLED=true`. Keep the test flag false.
