# WOVO YouTube and YouTube Shorts setup

This guide corresponds to WOVO's implementation in:

- `app/api/integrations/youtube/connect/route.ts`
- `app/api/integrations/youtube/callback/route.ts`
- `lib/publishing/providers/youtube.ts`

WOVO uploads through the official YouTube Data API v3. Shorts use the normal video upload API; YouTube determines Shorts eligibility from the resulting video.

## Step 1 — Open Google Cloud Console

Open [Google Cloud Console](https://console.cloud.google.com/) with the company-owned Google account that will administer WOVO's OAuth project.

## Step 2 — Create or select the WOVO project

Create or select a dedicated production project for WOVO Media. Do not use a customer's personal Google Cloud project.

## Step 3 — Enable YouTube Data API v3

Open **APIs & Services → Library**, locate **YouTube Data API v3**, and enable it.

## Step 4 — Configure the OAuth consent screen

Configure WOVO as an External web application. Use the WOVO Media logo, support email, developer contact, privacy policy, terms, and data-deletion URLs from `https://wovomedia.com`.

## Step 5 — Add verified domains

Add and verify:

```text
wovomedia.com
```

Complete Search Console/domain verification if Google requests it.

## Step 6 — Create Web application OAuth credentials

Create an OAuth 2.0 Client ID with application type **Web application**. Keep the client secret server-side.

## Step 7 — Add the exact redirect URI

Register this exact redirect URI:

```text
https://wovomedia.com/api/integrations/youtube/callback
```

It is generated by `socialRedirectUrl()` and stored with each one-time OAuth state. Do not add a trailing slash or query parameters.

## Step 8 — Configure WOVO's environment variables

Add these server-only Vercel Production variables:

```text
GOOGLE_YOUTUBE_CLIENT_ID
GOOGLE_YOUTUBE_CLIENT_SECRET
WOVO_SOCIAL_TOKEN_ENCRYPTION_KEY
WOVO_SOCIAL_MEDIA_HOST=wovomedia.com
WOVO_YOUTUBE_DATA_API_ENABLED=false
WOVO_YOUTUBE_PUBLISHING_ENABLED=false
WOVO_YOUTUBE_OAUTH_VERIFIED=false
WOVO_YOUTUBE_API_AUDITED=false
WOVO_YOUTUBE_TEST_UPLOADS_ENABLED=false
```

`WOVO_SOCIAL_TOKEN_ENCRYPTION_KEY` must be 64 hexadecimal characters and must never use a `NEXT_PUBLIC_*` name.

## Step 9 — Request only the upload scope

WOVO requests:

```text
https://www.googleapis.com/auth/youtube.upload
```

The current workflow does not request broad Google account access. If Google determines that channel discovery requires another scope during verification, document and justify it before changing the code.

## Step 10 — Preserve offline access

The connect route sends `access_type=offline` and `prompt=consent`. The callback fails closed if Google does not return a refresh token, because scheduled uploads must work when the customer is not in the browser. WOVO encrypts access and refresh tokens with AES-256-GCM and never returns them to the client.

## Step 11 — Complete OAuth verification

Submit the OAuth consent screen for verification. Provide a demonstration showing that WOVO uses the YouTube upload permission only after a customer selects a channel and approves or schedules a video. Do not set `WOVO_YOUTUBE_OAUTH_VERIFIED=true` before Google confirms verification.

## Step 12 — Complete the YouTube API audit

Google states that uploads from unverified API projects created after July 28, 2020 are restricted to private viewing. Submit the required YouTube API Services audit to lift that restriction. Until the audit is approved, WOVO allows only controlled private test uploads and rejects public/unlisted requests.

Do not set `WOVO_YOUTUBE_API_AUDITED=true` before written approval.

## Step 13 — Test with WOVO's YouTube channel

1. Add the WOVO test Google account as an OAuth test user.
2. Configure the callback and environment variables.
3. Set `WOVO_YOUTUBE_TEST_UPLOADS_ENABLED=true` only for the controlled test deployment.
4. Keep the audit flag false.
5. Connect WOVO's test YouTube channel.
6. Run **Check publishing** and confirm the channel ID/name and upload scope.
7. Upload one short, rights-confirmed WOVO-owned MP4 as `private`.
8. Confirm WOVO saves the returned video ID and tracks processing before marking the job published.
9. Confirm the private video exists in YouTube Studio.
10. Disable the test-upload flag after the canary.
11. After verification/audit, run one explicitly approved public canary and save provider proof.
